SMS 2 + CRAD — HostForge deploy checklist
==========================================

Same codebase as local. Only DB environment variables change.

Prerequisites
-------------
- GitHub repo is up to date (origin/main has the prefixed single-DB code).
- HostForge app is linked to https://github.com/khnny/sms2-capstone-v2-
- HostForge MySQL/MariaDB addon is provisioned (one database).
- You have the HostForge .env values (DB_HOST, DB_DATABASE, …).
  NEVER commit that file or paste the real password into the repo.


STEP 1 — Deploy code
--------------------
In HostForge:
1. Connect / redeploy from GitHub branch `main`.
2. Confirm the latest commit is live (should include config/tables.php
   and database/migrate_to_single_prefixed.php).
3. Document root should point at the project root (where index/login live),
   not a nested obsolete folder.


STEP 2 — Set environment variables (preferred)
----------------------------------------------
In HostForge → Environment Variables, set:

  DB_CONNECTION=mysql
  DB_HOST=<from HostForge .env — usually *.internal>
  DB_PORT=3306
  DB_DATABASE=hf_db_kn5x0oao
  DB_USERNAME=<from HostForge .env>
  DB_PASSWORD=<from HostForge .env>
  DB_CHARSET=utf8mb4

Optional (recommended for web migrate):
  SMS2_DEPLOY_TOKEN=<long random secret you invent>

Optional SMTP (Gmail App Password — recommended on HostForge so email
survives redeploys even if storage/keys/app.key is regenerated):
  SMS2_SMTP_USERNAME=your.account@gmail.com
  SMS2_SMTP_PASSWORD=xxxxxxxxxxxxxxxx

Optional live CAPTCHA (recommended):
  SMS2_TURNSTILE_SITE_KEY=<Cloudflare Turnstile site key>
  SMS2_TURNSTILE_SECRET_KEY=<Cloudflare Turnstile secret key>

Add the exact production hostname to the Turnstile widget's hostname list.
Environment variables take precedence over values saved in System Settings,
so they remain usable after a container redeploy.

Do NOT set a separate crad_db. CRAD uses the same DB automatically
(CRAD_DB_NAME falls back to DB_DATABASE / DB_NAME).

Optional explicit overrides (same value as DB_DATABASE):
  CRAD_DB_NAME=hf_db_kn5x0oao
  STUDENT_PORTAL_DB_NAME=hf_db_kn5x0oao
  REPORTS_DB_NAME=hf_db_kn5x0oao
  USERMGMT_DB_NAME=hf_db_kn5x0oao


STEP 2b — Fallback if env vars are unavailable
----------------------------------------------
On the server only (not in Git):
  copy config/local.hostforge.example.php → config/local.php
  fill YOUR_* placeholders with real HostForge values
  set SMS2_DEPLOY_TOKEN to a random secret

config/local.php is gitignored — never commit it.


STEP 3 — Backup HostForge DB
----------------------------
Before migrating, backup hf_db_kn5x0oao from HostForge / phpMyAdmin / CLI.


STEP 4 — Create schema (choose ONE path)

A) Empty HostForge database (fresh)
   Web terminal / SSH:
     php database/migrate.php

   Or browser (if SMS2_DEPLOY_TOKEN is set):
     https://YOUR-HOSTFORGE-URL/setup/deploy-db.php?token=YOUR_TOKEN
     Click "Run database migration"

   This applies sms2_* + crad_* dumps into DB_DATABASE.

B) HostForge DB already has OLD unprefixed tables (users, title_approvals, …)
   Web terminal / SSH:
     php database/migrate_to_single_prefixed.php --dry-run
     php database/migrate_to_single_prefixed.php

   Then create any tables that were missing:
     php database/migrate.php

After every release that adds a database migration, run `php database/migrate.php`
again from the HostForge web terminal. The current release adds durable image
storage for payment and signed-clearance uploads; this step is required before
the release can accept new uploads. New images are stored in managed MySQL,
so they survive container rebuilds and redeployments.


STEP 5 — First admin
--------------------
Open:
  https://YOUR-HOSTFORGE-URL/setup/

Create the Super Admin (if users table is empty / no admin yet).

If you imported local data that already has users, skip setup and log in
with an existing account instead.


STEP 6 — Verify
---------------
Web terminal:
  php database/tools/smoke_single_db.php

Expect:
  DB_NAME=hf_db_kn5x0oao  CRAD_DB_NAME=hf_db_kn5x0oao  Same DB: yes
  sms2_users count > 0 (after setup or data import)
  Smoke OK

Browser checks:
  - Login / logout
  - User Management
  - CRAD title approvals / proposals / panels / grants
  - No SQL errors about missing `users` or `crad_db`


STEP 7 — Harden
---------------
- Remove SMS2_DEPLOY_TOKEN from env / local.php after migrate succeeds.
- Confirm no real password is in any committed file.
- Keep HostForge *.internal host — it only works from HostForge, not XAMPP.


Local vs HostForge reminder
---------------------------
Local XAMPP:   DB_HOST=localhost   DB_DATABASE=sms2_db
HostForge:     DB_HOST=*.internal  DB_DATABASE=hf_db_kn5x0oao

Same PHP. Same sms2_* + crad_* tables. Config only.


Troubleshooting
---------------
"Database unavailable"
  → Env vars not injected, or DB_HOST is wrong for the container.

"Unknown table users" / "sms2_users"
  → Migration not run, or PHP code/DB prefix mismatch. Re-deploy latest main
    then run migrate / migrate_to_single_prefixed.

"sms2_db.users" errors
  → Old code still deployed. Pull/redeploy latest main.

Cannot connect from your PC to mariadb-*.internal
  → Expected. Use HostForge terminal / phpMyAdmin, not local XAMPP.

"SMTP password is missing or could not be decrypted"
  → Encrypted DB secret lost after app.key rotated, or never saved on HostForge.
    Fastest fix: set HostForge env SMS2_SMTP_PASSWORD to your Gmail App Password
    (no spaces needed), redeploy/restart app, then Test email in System Settings.
    Also set smtp_host=smtp.gmail.com, port 587, TLS, and smtp_username in
    System Settings if those are empty.
